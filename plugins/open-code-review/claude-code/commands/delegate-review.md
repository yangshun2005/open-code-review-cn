以委派模式调用 OpenCodeReview (OCR)。OCR 决定审查哪些文件并提供审查规则；您使用自身能力执行实际代码审查。

## 工作流程

### 步骤 1：预览

```bash
ocr delegate preview [user-args]
```

- 默认（无用户参数）：工作区模式（已暂存 + 未暂存 + 未跟踪）。
- 如果用户提供 `--commit` 或 `-c`：原样传递。
- 如果用户提供 `--from` 和 `--to`：原样传递。
- （可选）提供 `--background "context"` 或 `-b "context"` 以添加业务上下文。
- 如果未找到 `ocr`，请安装：`npm i -g @alibaba-group/open-code-review`。

此命令输出模式/引用元数据及可审查文件列表。

### 步骤 2：获取规则

传递所有可审查文件路径以获取其审查清单：

```bash
ocr delegate rule <path1> <path2> ...
```

### 步骤 3：获取差异并审查

对于每个可审查文件，使用 git 获取其差异（基于步骤 1 中的模式/引用）：
- 范围：`git diff <merge_base>..<to> -- <path>`
- 提交：`git show <commit> -- <path>`
- 工作区：`git diff HEAD -- <path>`（或直接读取未跟踪文件）

然后重点审查：正确性、安全性、性能、错误处理、并发性、可维护性。仅对变更代码（+ 行）发表评论。

### 步骤 4：报告与修复

按严重程度对每个问题进行分类：

- **高**：明显错误、安全问题、数据丢失或具有精确修复建议的明确失误
- **中**：合理的关注点、性能建议或需要手动操作的修复
- **低**：静默丢弃（可能是误报、吹毛求疵或上下文不足）

自动修复安全且定义明确的高和中级问题。
