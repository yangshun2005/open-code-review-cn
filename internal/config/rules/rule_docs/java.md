#### 明显拼写错误或拼写错误
- 变量名、方法名或类名在声明处的拼写错误（通过使用 `code_search` 搜索类似标识符的命名约定来确认）
- 日志消息或异常消息中包含影响可读性的拼写错误的字符串
- 不要报告引用位置的拼写错误，因为这些通常由声明决定

#### 死代码
- 永远无法到达的代码块（例如，条件始终为假的分支、return 语句之后的代码）
- 已声明但从未读取或引用的变量
- 大块注释掉的代码（无明显保留意图）

#### 逻辑错误检测
- 错误的 if 条件逻辑（使用 `file_read` 检查周围上下文并确认预期逻辑）
- 边界条件处理错误（特别注意索引和数组长度检查）
- 布尔逻辑运算符的误用（优先级和短路求值问题）
- 明显的无限循环或没有终止条件的递归
- 在不打算退出时使用 return/break/continue
- switch 分支中缺少 break 语句导致意外穿透
- 有意的穿透但缺少解释性注释
- 可能导致 NPE 的代码模式（通过使用 `file_read` 和 `code_search` 检查数据源调用链来确认风险）
- 逻辑表达式中缺少括号，可能导致执行顺序与预期不符

#### 严重性能问题
- 循环内执行的数据库查询（使用 `code_search` 确认方法调用是否涉及数据库操作）
- N+1 查询问题（建议批量查询优化）
- 处理大数据集时未进行分页（使用 `file_read` 了解数据规模和处理上下文）
- 嵌套循环中的低效算法实现（O(n^2) 或更高复杂度，而存在更优解决方案）

#### 线程安全问题检测
仅在以下情况下标记线程安全问题：
- **竞态条件**：存在“检查后执行”模式，中间状态可能被其他线程修改
- **非原子复合操作**：需要原子性但缺乏同步机制的多步骤操作
- **不安全的懒加载**：单例模式或缓存实现中的双重检查锁定缺陷
- **对非线程安全集合的并发写入**：在多线程环境中修改非线程安全的集合，如 ArrayList 或 HashMap

以下情况不要报告：
- **方法内的局部变量**：这些本质上是线程安全的，因为每个线程都有自己的副本
- **单线程上下文使用**：没有多线程调用的证据（通过使用 `code_search` 搜索相关调用上下文来确认）
- **只读操作**：即使使用非线程安全的数据结构，如果只执行读取操作
- **不可变对象**：指向不可变对象的 final 字段引用
- **已有正确的同步机制**：代码已使用 synchronized、Lock、原子类或其他正确的同步机制
- **设计为单线程使用的组件**：如 Builder 模式的构建阶段、临时数据传输对象等。
