#### PHP 审查原则
> 优先精确而非召回：仅报告变更代码及其可达上下文中可能真实存在的缺陷。将正确性和安全问题视为阻塞性问题；仅涉及风格的建议为非阻塞性。在报告与版本或生命周期相关的行为之前，需考虑项目的 PHP 版本和框架约定。

在做出非局部声明之前，请使用 `file_read` 和 `code_search` 验证调用者、输入来源、框架配置、模板上下文和资源所有权。除非差异展示了 PHPStan、Psalm、PHP_CodeSniffer、格式化工具或 PHP 编译器未明确表达的具体后果，否则不要重复报告这些工具已可靠强制执行的发现。

#### 类型转换、相等性和 Null 语义
- 松散比较（`==` 或 `!=`）可能导致安全或领域敏感的不同值被强制转换为相等。当操作数预期具有相同类型时，优先使用严格比较；不要标记经过验证的有意规范化。
- 真值或 `empty()` 检查错误地将 `0`、`"0"`、`false`、`null` 和空值视为等价，而这些状态具有不同含义。
- 当存在键但值为 `null` 时需与缺失键区分时，使用 `isset()`；当存在性（而非非空性）是约定时，使用 `array_key_exists()`。
- 可空、联合类型或返回 `false` 的 API，其失败值到达假定可用对象、标量或资源的代码。在标记前确认声明和运行时约定。
- 数字字符串、算术或比较行为依赖于与 `composer.json`、CI 或部署配置支持的 PHP 版本不同的版本。

#### 数组、迭代和值语义
- 读取数组键时未处理可达的缺失键路径，尤其是请求数据、解码后的 JSON、数据库行或可选配置。
- `foreach` 值变量通过引用迭代后未使用 `unset()` 即重用，导致其别名指向最后一个元素，后续赋值可能破坏数组。
- 数组联合（`+`）、`array_merge`、展开语法或数字键重新索引的语义与预期的覆盖和排序行为不同。
- 回调或闭包通过引用捕获循环变量，随后观察到意外的最终值或修改后的值。
- 迭代期间的修改可能导致跳过、重复或意外保留元素。不要标记遍历行为有意且局部明显的修改。

#### 错误、异常和 API 约定
- 捕获 `Throwable` 或 `Exception` 后静默丢弃、转换为成功，或在失败重要的路径上替换为误导性默认值。
- 在无关操作周围捕获宽泛异常，导致处理程序无法区分预期失败与编程或基础设施缺陷。
- 代码库约定不一致地混合使用异常、`false` 和 `null` 表示同一失败，导致调用者错过错误路径。
- 清理、回滚或响应完成代码隐藏了主要异常或在操作失败后返回成功。
- 使用 `@` 抑制警告或错误，而抑制可能将有意义的失败转化为无效状态。不要标记范围明确且安全检查结果的兼容性探测。

#### 资源、事务和请求生命周期
- 在长时间运行的进程中，事务、锁、数据库游标或资源未在每个可达路径上释放、提交或回滚，延迟清理可能导致容量耗尽或破坏正确性。不要仅仅因为 PHP 可以在请求关闭时释放普通请求作用域的流或文件而标记它们。
- 数据库事务存在提前返回或异常路径，可能导致事务保持打开，或嵌套事务假设不受当前驱动/框架支持。
- cURL 或流操作在请求或工作路径上缺少超时，远程端点可能使执行停滞。
- 会话锁在慢速网络、数据库或 CPU 工作期间持有，而同一会话的并发请求必须继续。
- 当所有权转移由周围代码确立时，不要报告框架、依赖注入容器、生成器消费者或调用者拥有的资源。

#### 数据库和 ORM 正确性
- SQL 从未受信任的值组装，而非使用参数绑定。列名和排序方向等标识符通常无法绑定，需要白名单。
- 原始 ORM 表达式、查询片段或动态表/列名绕过框架的正常参数化，使用攻击者控制的数据。
- 当变更的多步骤写入必须原子化时缺少事务边界，或副作用顺序导致回滚无法恢复一致性。
- 仅当循环在有效规模下可达且预加载或批处理保持行为时，才报告 N+1 查询或重复远程调用。
- 仅当请求控制的字段到达模型且框架的 fillable/guarded/schema 配置未约束它们时，才报告批量赋值暴露。

#### Web 和模板安全边界
在报告前确认攻击者控制以及输出或执行上下文。框架验证和自动转义可能使看似危险的操作变得安全。

- 未受信任的输出未按 HTML 文本、属性、URL、JavaScript 或 CSS 的上下文进行适当转义。对于 `.phtml` 模板，验证视图助手是否已转义值，以及原始 HTML 是否有意且已消毒。
- 授权仅在客户端、模板或隐藏控件中强制执行，而非在服务器端操作中；标记前检查路由中间件、策略、投票器和控制器守卫。
- 当基于 Cookie 的身份验证使跨站调用成为可能时，状态更改的浏览器请求缺少必需的 CSRF 保护。不要标记不易受环境凭据影响的令牌认证 API。
- 重定向、响应头或 Cookie 由未受信任的数据构建，未进行验证或缺少必要的 `Secure`、`HttpOnly` 和 `SameSite` 保护。
- 文件上传仅信任客户端文件名、扩展名或 MIME 头；验证服务器端类型检查、生成的存储名称、目标边界和可执行文件处理。
- 用户控制的路径用于文件系统访问，未进行规范化和边界强制，导致路径遍历、符号链接逃逸或意外覆盖。

#### 动态执行、反序列化和出站请求
- `eval`、动态 `include`/`require`、变量函数调用、反射或 shell 命令由未受信任的输入到达，且无严格白名单。
- 对攻击者控制的数据使用 `unserialize()`，包括缺少密钥管理或验证的签名数据。优先使用非可执行格式；`allowed_classes` 减少对象注入，但不能使任意数据可信。
- 通过拼接或不完整转义构建 shell 命令。优先使用带单独参数的直接进程 API，并验证类似选项的攻击者控制值。
- 出站 URL 由未受信任的输入派生，未进行必要的 scheme、host、port、redirect 和私有网络限制，导致 SSRF 或凭据转发。
- 弱随机性或密码处理：可预测的令牌生成、可逆密码存储、手动密码哈希或非恒定时间比较秘密。酌情优先使用 `random_bytes`、`password_hash`、`password_verify` 和 `hash_equals`。
- 秘密、会话标识符、授权头、密码、私钥或敏感个人数据被记录、在错误中返回或嵌入源代码。

#### 性能和审查范围
- 仅在有意义的数据规模或热路径证据时报告性能问题：重复查询、意外全结果物化、二次方数组操作或循环内重复的昂贵工作。
- 仅针对涉及强制转换、边界值、错误、事务、授权、转义或框架配置的具体变更失败模式建议测试。
- 不要将格式化、命名、导入排序、现代语法偏好或已由确定性 PHP 工具强制执行的建议作为阻塞性发现。
