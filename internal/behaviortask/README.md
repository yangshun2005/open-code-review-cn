# 行为/影响任务

本包使用 `llmloop.Task` 实现一次只读调查。它不改变 `ocr review` 或 `ocr scan`，不启动 MCP，不构造评论收集器，不执行仓库代码，也不调用报告摘要模型。`ocr review --commit <sha> --analysis` 和 `ocr review --from <base> [--to <head>] --analysis` 通过 `internal/workflow` 将完整 Review 流水线与这个独立任务组合。未提交的更改请使用普通 `ocr review`，不加 `--analysis`。该可选标志不改变默认的 review 或 scan 成本。两个角色使用配置的模型，并共享一个公开报告 ID。分析最多额外发起一个并发模型请求。两个角色对每个提示使用解析后的 `--max-tokens` 限制，并共享一个 `--max-git-procs` 池。分析默认没有总 token 限制（`--analysis-max-tokens-budget 0`）。正数限制统计调查、压缩和最终提交的 token。进行中的请求和一次仅提交的最终轮可能使总量超出限制。Review 摘要和 Analysis 元数据分别报告各自用量。Analysis 失败不改变 Review 的退出状态；命令取消对两个角色都生效。

## 准备边界

调用方是可信的准备层，不是模型输出。在 Review 准备路径中解析一次比较端点，然后将得到的 SHA 值传给 `PrepareInput`，以获得比较的完整授权 diff 清单，包括删除和重命名。它忽略调用方提供的 diff，也不使用 Review 的选中文件列表。两个角色都使用 head 提交的根 `.gitignore` 过滤变更路径。这过滤的是 diff，不是对支持上下文的读取或搜索。提供捕获的上下文时需附带来源和用户排除项。绕过 `PrepareInput` 的直接库调用方仍需自行负责将其 diff 绑定到这些端点。提交和范围补丁使用 head 修订的版本化属性。如果活动 Git 环境以 Analysis 无法复现的方式覆盖仓库、索引或命令配置，则跳过。两个 API 都不会重新发现 PR 或获取缺失对象。

`NewRunner` 接受完整 SHA 的范围和提交比较；根提交的旧侧是空树。它构造现有的 old/new `CodeAccess`，并在报告中记录自己的 trace。文件内容来自选定的修订，而非实时工作树。显式排除项、内置排除目录、类凭据路径、符号链接和不支持的路径通过读取、搜索、枚举和 diff 均不可用。未变更的授权消费者仍可读取。这不是针对恶意本地 Git 配置或提供虚假数据的准备层的沙箱。

传入位于被分析仓库之外的新鲜 `Deps.ArtifactDir`，其父目录必须存在。已存在的目录会被拒绝。使用 `Run(ctx)` 运行一次。调用方拥有 LLM 客户端配置；任务从不选择不同的模型。自定义 `BehaviorTemplate` 可以更改预算和语言，而不改变 Review/scan 模板。使用 `Deps.Language` 设置散文语言（默认英语）；schema 标识符和枚举值保持不变。

## 证据与提交

每次执行的代码/上下文读取都会返回并持久化一条观察记录，包含其比较身份、规范化参数、返回文本哈希、精确观察位置、截断和错误分类。相邻的观察行共享一个范围；搜索结果中的间隙保持为间隙。适配器不会虚构总搜索计数。文件枚举仅匹配授权路径，当超过 100 个授权路径匹配时报告截断。

`context_read` 读取注入材料、分页清单索引或现有观察。其游标是 UTF-8 字节偏移，默认页大小为 16 KiB（最大 64 KiB）。重放观察不会创建另一个证据身份。上下文索引保留来源和内容哈希。缺失的元数据不能通过对 CI 或依赖行为的推断来替代。

`submit_analysis` 是唯一的完成工具。其 v2 契约要求一个 `markdown` 字符串，可选 `declared_completion`（`complete`、`partial` 或 `unknown`；省略则为 `unknown`）。Markdown 限制为 256 KiB UTF-8，且不能仅含空白。标题、排序、列表、表格和散文不会被解析为语义 schema。提示要求简洁的维护者简报：结论先行，每个实质影响只出现一次，保留决定性条件、后果和证据。行为和影响可以合并；省略空章节、重复背景和调查叙述。简洁不缩小调查范围、不施加硬性长度上限，也不移除独立风险。当证据支持采取行动时，简报以针对已证明契约违规的修复、具体验收检查或真正的维护者选择结尾。未经验证的假设不是阻塞项，提议的检查不是测试结果。

使用字面量 `[[obs-000001]]` 标记引用工具观察。验证仅检查标记语法以及每个引用的 ID 在本次运行中存在且无错误分类。标记即使在代码块内也保留。程序推导 `cited_observation_ids`；允许未引用报告，其列表为空。它不检查每个散文声明、行位置、old/new 归属、因果关系、执行声明或证据是否支持结论。精确观察位置和验证来源保留在观察日志中供人工检查。找到源测试仍不能证明它运行过。

无效提交可在现有对话预算内修复。第一个有效报告被冻结。分析默认 300 轮调查。如果耗尽轮次或 token 预算，最多可额外进行一轮，仅使用 `submit_analysis`；无效的最终提交不会重试。`Result.Completed` 表示循环接受了提交，而非调查已完成或正确。`workflow.Report.Status` 描述执行情况，与模型声明的完整性分开。自我声明为部分的报告可以成功交付；完整声明永远不会覆盖预算停止、取消、提供方错误或构建产物持久化失败。

## 构建产物与验证

- `result.json`：`ocr.behavior-impact/v2` 元数据，包括执行状态、模型评估、比较、范围、停止原因和用量。CLI 在准备输入前记录 `started`，并在完成时原子替换。
- `report.md`：接受的 Markdown，与提交时完全一致，不含生成的标题。
- `observations.jsonl`：仅追加、运行本地的证据。持久化失败会停止任务，而不是接受无法恢复的证据。
- `trace.jsonl` 捕获模型调用、压缩和工具结果。设置 `OCR_RAW_LOGGING=1` 时，`raw.jsonl` 还捕获原始 Analysis HTTP 尝试。后台工作在会话和结果最终化之前汇合。

通过 `make test PACKAGES='./internal/behaviortask'` 运行单元测试。将 `OCR_BEHAVIOR_REPLAY` 设置为已验证的交接重放目录，以额外使用**fixture 客户端**（而非真实模型）运行三个固定冒烟输入。该测试检查工程集成并保留显式部分结果；它既不读取评估标准，也不衡量 Behavior/Impact 质量。在前后运行交接辅助工具的验证。不要格式化或在历史源视图中运行测试。

仍待完成：固定模型评分重放和消融（2A-4）。快照完整性、fixture 客户端测试和针对本地 mock 端点的二进制重放属于工程验证，而非对真实模型分析质量的验收。
